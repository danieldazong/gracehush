## The shared playback store

`src/store/playerStore.ts` (Zustand, not persisted) holds what the mini player and Now Playing both show. Steps 15, 26 and 27 read these names, so use them exactly (steps may add fields and actions, never rename).

```ts
// src/types/index.ts
export type PlaybackStatus = "idle" | "playing" | "paused" | "ended";
export type PlaybackRate = 0.8 | 1 | 1.2;
export type PlaybackTrack = { entryId: string; title: string; subtitle: string; durationMs: number };
export type AmbientDefault = Pick<UserProfile, "ambientSound" | "ambientVolume">;

// src/constants/app.ts
export const SKIP_MS = 15_000;
export const PLAYBACK_RATES: readonly PlaybackRate[] = [0.8, 1, 1.2];
export const AMBIENT_SOUNDS: readonly AmbientSound[] = ["off", "soft-rain", "gentle-piano", "morning-birds"];
```

State: `entryId: string | null`, `title`, `subtitle`, `durationMs`, `positionMs`, `status`, `rate`, `ambientSound`, `ambientVolume` (0 to 1). Actions: `load(track, ambient)`, `play()`, `pause()`, `toggle()`, `seekTo(ms)`, `skipBy(deltaMs)`, `setRate(rate)`, `setAmbient(sound)`, `setAmbientVolume(volume)`, `stop()`. `src/hooks/usePlayback.ts` is a one-line hook that returns the whole store (`usePlayerStore()`); screens and components use only this hook, never the store. A component that calls it re-renders on every tick, so only `MiniPlayerCard`'s `AudioCard` and `NowPlayingScreen` call it: the Reflection screen itself must not.

Rules (a Node harness with a fake clock proved every one of them: 54 checks, 0 failures). The reviewed drafts are outside the repo, in the scratchpad: `C:\Users\PC\AppData\Local\Temp\claude\c--Users-PC-Desktop-gracehush\a8f2e38c-cafe-4dae-81a3-8275d0a0dcb7\scratchpad\p12\playerStore.ts`, `ProgressScrubber.tsx` and `test.js` in that folder. They are drafts, not the spec: this prompt wins, and the final code must be written into the repo's own conventions (comments, copy, typing).

- **`load(track, ambient)` is synchronous.** The same `entryId` does nothing, so reopening a reflection never resets its position. A different `entryId` clears the timer and sets the track fields, `positionMs: 0` and `status: "paused"`. `rate` and the ambient choice are kept across loads (a listener's speed and sound belong to the session, not to a devotional). The first `load` after the app starts, or after `stop()`, also copies `ambient.ambientSound` and `ambient.ambientVolume` into the store (a module-level `ambientSeeded` flag); later loads keep the session values. Callers pass the profile they already have (`ambient` is `AmbientDefault`, a `UserProfile` fits): the store never fetches. `// TODO(27): persist the ambient choice to users_profile` on `setAmbient` and `setAmbientVolume`.
- **The tick** is one module-level `setInterval` of 250 ms, running only while `status` is `"playing"`. It advances by the time that really passed times the rate (`(now - lastTickAt) * rate`), not by a fixed 250: JS timers run late here (measured up to 8.7 s on the emulator while it was busy), and a fixed step would make the clock lag. `startTimer` always clears first, so there is never more than one interval. At the end it clamps `positionMs` to `durationMs`, sets `"ended"` and clears the timer.
- `play()` does nothing with no track loaded; from `"ended"` it restarts at 0. `pause()` does nothing unless playing. `seekTo` and `skipBy` clamp to `[0, durationMs]`; reaching the end sets `"ended"` and clears the timer; seeking back from `"ended"` sets `"paused"`; seeking while playing keeps playing.
- `setAmbientVolume` clamps to `[0, 1]`.
- **`stop()` is a full reset**: clear the timer, `entryId: null`, empty title and subtitle, position and duration 0, `status: "idle"`, `rate: 1`, ambient `"off"` and 0.5, and clear `ambientSeeded`, so the next signed-in user's first `load` reads their own profile. Step 15's `signOutCleanup` calls it (step 31's account deletion runs that cleanup too). `load` with a different entry does not call it (that would forget the session's speed and sound).
- **The app leaving the foreground pauses** (one module-level `AppState` listener). Nothing is audible in this mock, so nothing should keep counting while the user is away; step 11's hook did the same. Marked `// TEMP(26)`: real audio keeps playing in the background, so step 26 removes it.
- Leaving Now Playing or Reflection does **not** pause (step 11's pause on losing focus is gone): playback stops only when another devotional is loaded, `stop()` runs or the app leaves the foreground. This is how step 26's real audio behaves.
- The file starts with `// TEMP(26): replace the internals with the real player; keep the state names and the action names`. No `console.log`, and nothing from a transcript, devotional or prayer is ever logged.

**Load on the user's action, not on view.** The draft called `load()` whenever Reflection showed an entry with audio. That makes opening the Journal entry B stop entry A that is playing, and with step 26's real audio it would also mint a signed URL for every entry merely looked at. Instead nothing loads until the user acts on a player: the mini player's first play, or opening Now Playing (from the card, or by route). `MiniPlayerCard` therefore compares `player.entryId` with its own track: if it is not the loaded one it shows 0:00 and paused, and its play button calls `load(track, ambientDefault)` and then `toggle()`.

`getPlaybackTrack(entry: JournalEntry): PlaybackTrack | null` goes in `src/data/selectors.ts` (a pure derived value). It returns `null` for a crisis entry, for any entry whose `status` is not `"ready"`, and for a devotional with a null `audioPath` or a null or non-positive `durationMs` (an unmeasured length is never invented, AGENTS.md "Audio Rules"); otherwise `{ entryId: entry.id, title: devotional.title, subtitle: copy.nowPlaying.subtitle(entry.scripture?.reference ?? null), durationMs }`. The mini player and Now Playing both build their track with it, so a crisis entry can never reach a player.

## `ProgressScrubber` (`src/components/ProgressScrubber.tsx`)

The only new reusable component: it is the main scrubber here, the volume slider here, and the Profile's ambient volume in step 15. Props: `value`, `max`, `step` (what a screen reader's increment and decrement move), `color`, `trackHeight`, `disabled?`, `accessibilityLabel`, `formatValueText(value): string`, `onSeekStart?()`, `onSeekChange(value)`, `onSeekEnd(value)`. It is controlled: it holds no value of its own, so a parent that wants to ignore store ticks while dragging keeps the dragged value in its own state (the player screen does; the volume row does not need to).

- A 44-tall `View` with the track (`trackHeight`, full radius, `petal` background, `overflow: "hidden"`, the fill width a percentage) centered in it and a 16 circle thumb (`position: "absolute"`, `left: ratio * width - 8`, the same colour, `shadows.card`). Both children are `pointerEvents="none"`. `onLayout` gives the width. Dynamic styles are inline (AGENTS.md Style Exception Rules).
- **Touch handling is the view's own responder props, not `PanResponder`.** `onStartShouldSetResponder` and `onMoveShouldSetResponder` return `!disabled`; `onResponderTerminationRequest` returns `false` (the screen is a vertical `ScrollView`, and a drag must not turn into a scroll). On grant it records `pageX` and `locationX` and calls `onSeekStart` and `onSeekChange(valueAt(event))`; on move `x = grabX + (pageX - grabPageX)` and `value = clamp(x / width, 0, 1) * max`, so the value follows the finger even beyond the ends of the track; on release **and on terminate** (the system took the touch) it calls `onSeekEnd` with the last value, so a parent's drag state always ends. A tap anywhere on the track seeks there. The grab lives in a `useRef` that only the handlers touch. `PanResponder` was rejected because it is created once and would hold stale callbacks.
- Accessibility: `accessible`, `accessibilityRole="adjustable"`, `accessibilityValue={{ min: 0, max, now: value, text: formatValueText(value) }}`, `accessibilityActions` increment and decrement, and `onAccessibilityAction` calling `onSeekEnd(clamp(value ± step, 0, max))`. For the player `step` is `SKIP_MS` and the text is "34 seconds of 1 minute 15 seconds" (`formatDurationSpoken`, through `copy.reflection.player.position`, as the mini player already speaks it).

## The screen (`src/screens/journal/NowPlayingScreen.tsx`)

The route's `entryId` is the entry. The screen reads `usePlayback()` and also calls `useReflection(entryId)` (it already loads the entry and the profile, handles loading, not found and error, and it is how a player opened any other way gets its track). It is the **loaded** player when `player.entryId === entryId`, and then it renders from the store alone: a failed or slow `useReflection` must never hide a player that is already running. Otherwise:

- `useReflection` loading, or ready but not yet loaded (one frame): the loading skeleton (below).
- error: `MessageView` with `copy.nowPlaying.states.error`, a `PrimaryButton` "Try again" (`state.retry`) and a text link "Close".
- not found, **or a crisis entry** (it must not even hint that a player exists for it): `MessageView` with "We couldn’t find this devotional." and a `PrimaryButton` "Close".
- ready, but `getPlaybackTrack(state.entry)` is null (no audio yet, or processing or failed): `MessageView` with "This devotional’s audio isn’t ready yet." and a `PrimaryButton` "Close". Never start playback.
- ready with a track: `useEffect(() => { load(track, state.profile) }, [...])` (a store action called from an effect passes the lint rules; checked), and the next render is the loaded player.

Export `MessageView` from `ReflectionStateViews.tsx` for this (it is the second use of the same calm message, and the file already holds it); change nothing else in that file. The header row (Close) shows in every state, above the state's body.

## Rules

- No real audio, no network, no new dependency. No `any`. NativeWind classes for everything they can express; `StyleSheet` or inline for dynamic values, the transform array, `LinearGradient` and the shadow objects (AGENTS.md Style Exception Rules). A `Pressable` takes only a `style` function, with the classes on an inner `View` (it cannot take both).
- Never log transcript, devotional script, prayer text, titles or ids. The store logs nothing.
- Crisis: a crisis entry never loads, never shows a player and never reaches the lock screen. No sounds, no haptic and no animation for it anywhere (AGENTS.md "Crisis Safety Rules"; step 13 builds its real view). If you are unsure whether a change touches crisis handling, stop and ask.
- Every interactive element has a role and a label that includes its state. Text beside a chip, icon or button is `flex-1` or `shrink` (React Native's default is no shrink), and the ambient card's header and chip rows wrap instead of squeezing a word.
- Do not change Reflection's layout or copy beyond the mini player wiring, do not touch `SegmentedControl`, `FadeIn`, `Skeleton` or `PrimaryButton`, and add no colour, font, radius or shadow.
