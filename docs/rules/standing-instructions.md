# Standing instructions (the full wording)

> Part of the GraceHush rules, moved out of `AGENTS.md` word for word on 2026-11-23. `AGENTS.md` is the short core that every session loads, and its "Rules index" says which file holds which section. The sections below keep their original `##` headings, so a reference such as "AGENTS.md, Crisis Safety Rules" finds them. ## Instructional Memory

- **Publishing never exposes a secret or an identifying value (2026-10-22, repeated 2026-10-23).** The GitHub repository is public. No committed file (code, AGENTS.md, a prompt, a test, a commit message) holds a key, a token, the contents of a `.env.local`, the Supabase project ref, the Clerk instance domain, an EAS username, an Apple Team ID or Key ID, the length of a key, a local path, a personal email address, the Google billing account id, a card's digits or the Google Cloud project id. - **After every implemented step, ask whether to start the guided phone walk-through (2026-10-26, restated 2026-10-27).** When a step prompt is implemented and its automated (Part A) checks pass, the agent ends its report by asking the user, in one line, whether to start the step's "Part B: the phone walk-through" now, and waits for the answer. It does not start the walk-through, and does not ask for results one check at a time, until the user says yes. The walk-through is a guided, human-in-the-loop test on the user's iPhone: the user does the physical actions and the dashboard actions, and the agent checks every result itself by reading the running app through the dev server's inspector (read-only) and the database, then reports PASS or FAIL with evidence. On 2026-10-27 the user gave the protocol again in a general form, with a project setup to fill in once: "Guided phone walk-through" under Linting and Validation holds it, set up for this project, and `prompts/TEMPLATE.md` says how a step prompt writes its checks. That form added four rules: the agent never takes the user's word as the only evidence when it can read the result itself; a FAIL is fixed only after the user's yes, and its check is then run again; what cannot be checked on the target is listed separately, with where it can be; and the user is never asked to test what cannot work on the target. It applies to every step prompt, also those written before this rule (their "say 'guide me'" lines are answered by this question).
- **Siri cannot be tested on the user's iPhone (2026-10-27).** Siri on it does not work, so no walk-through check may need Siri. A step prompt's Siri check is reported as "not tested on a device", and what the app does when Siri speaks is set by the Audio Rules (Playback, "Interruptions follow the platform") and not left open for a test. If a step needs an interruption tried, use one the phone can produce: a timer or alarm that rings, or a call from another phone, and only if the user can arrange it. Do not ask for a Siri test again.

- **A processing screen holds a person for about three seconds, never for the server's work (2026-11-09, restated 2026-11-10).** The owner found the 30-second New Entry processing screen a retention killer and asked for about three seconds with no loss in the reflection's quality, built "as Google, Facebook or Amazon would build it", and on 2026-11-10 that the screen with its three step cards stay. The server's own work (the model 5 to 10 seconds, a retry for about a third of reflections, the speech 12 to 15 seconds) cannot be three seconds on the model the owner chose, so the pattern is send-and-go: the screen keeps the three step cards, each ticking only on a moment the phone knows for sure, and hands the reflection to its own screen at three seconds (Reflection, which shows it being prepared and fills in when the server has finished; the owner also asked, the same day, that the Journal show no progress card for it, because the overlay already shows the progress), while the server answers with the text and reads it aloud behind the answer. Any future flow that waits on the server follows the same rule: progress shown in place, the answer delivered progressively, and no screen that holds a person longer than a few seconds.
