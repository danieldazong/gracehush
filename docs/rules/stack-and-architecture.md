## Architecture Guidelines

Use this structure unless there is a strong reason to change it:

```txt
gracehush/
├── App.tsx, index.ts      # providers and the splash gate; registerRootComponent
├── app.json, app.config.ts, eas.json, metro.config.js, global.css
├── assets/                # fonts, images, audio, expo.icon
├── docs/                  # legal pages and the site build; build-log.md, vendor-notes.md, architecture-tree.md
├── plugins/               # local config plugins (withSplashFooter)
├── prompts/               # step prompts, TEMPLATE.md, DESIGN.md, a copy of this file
├── src/                   # api, components, constants, data, db, hooks, navigation, screens, services, store, types, utils
└── supabase/              # schema, migrations, Edge Functions (functions/), tests
```

The full tree, with what each file holds, is in `docs/architecture-tree.md` (moved there on 2026-11-23 to keep this file small). Find a file or a name with `git grep -n "<name>" docs/architecture-tree.md` and read only those lines; never read it whole. A file added, moved or deleted gets its line there in the same step.

`src/app/` (the Expo Router template) was deleted in step 03. Do not recreate it. Screens are plain components registered in `RootNavigator`.

### src/screens/

Use this for screens only.

Screens compose components and call hooks, stores, and services. They should not contain large reusable UI blocks, network calls, or business logic.

### src/api/ and src/services/

- `api/` holds HTTP calls to Edge Functions. Each call returns typed data or a typed error.
- `services/` holds device and SDK wrappers (audio, notifications, purchases, Supabase client).
- Screens never call `fetch` directly.

## State Management Rules

Use Zustand for global client state:

- onboarding progress and reminder times
- current playback state (track, position, speed, ambient)
- sync queue status and connectivity
- entitlement snapshot for UI gating
- app settings

Use local component state for temporary UI state (segmented tabs, sheet visibility, form inputs).

Do not mirror server data in Zustand if it already lives in the local SQLite cache. Read it through hooks.

Persist settings with AsyncStorage only when they don't belong in the profile table. Never persist journal text in AsyncStorage.

**Onboarding store (step 07).** `src/store/onboardingStore.ts` persists `hasCompletedOnboarding`, `completedAt`, `reminders` (`"HH:mm"`, 24-hour, keep that format), `permissionsPromptedAt`, `remindersSyncedAt`, `remindersDirty`, `analyticsConsent` and `hasSignedIn` under the key `gracehush.onboarding` (version 5). The current step index and any permission status are not persisted: the OS is always the source of truth for permissions, and relaunching mid-flow starts at Welcome with the saved times. Every persisted store uses `src/store/safeStorage.ts`, validates every field in its own `merge` (zustand's default merge is shallow), and is gated with `useStoreHydrated` wherever the first render depends on it (`AppShell` holds the splash until it is true). No journal text or other sensitive value goes into AsyncStorage: this store holds only flags, times and timestamps. Since step 17 `services/profileSync.ts` keeps `reminders` in step with `users_profile` (since step 18 in the same request as the three settings and the time zone). Version 2 added `remindersDirty` (an edit the server has not seen) and three actions: `markRemindersSynced`, `applyServerReminders(times)` (the server's times replace the device's and the edit flag clears) and `discardUnsyncedReminders` (sign-out: an unsent edit belongs to the account that made it). `migrate` treats a version 1 save whose time differs from the default and was never synced as unsent, so an existing install keeps its times. The rule: equal times need no move, an unsent edit is pushed, otherwise the server's times are applied. Version 3 (step 34) added `analyticsConsent` (asked on the Journal's first visit since round 8 of 2026-11-01). Version 4 (step 34b) added `hasSignedIn` and the idempotent `markSignedIn`: `RootNavigator`'s signed-in effect marks the device, Sign In reads it, sign-out keeps it (it belongs to the device, like the reminder times) and `resetOnboarding` clears it. An older save migrates with `hasSignedIn` equal to `hasCompletedOnboarding`, because the returning-user rule marks onboarding complete for any signed-in session. ## TypeScript Rules

Use TypeScript strictly.

Avoid `any`, including in Edge Functions. Type Gemini, HelloAO, and TTS responses explicitly.

Keep app models and the process-entry contracts (`TimeSlot`, `JournalEntry`, `ProcessEntryRequest`, `ProcessEntryResponse`, `ProcessEntryErrorCode`) in `src/types/index.ts`, and mirror the contracts in `supabase/functions/process-entry/contracts.ts` (step 19; types only, no imports). `src/types/contractParity.ts` makes any difference between the two copies a type error. Database row types come from the generated `src/types/supabase.ts` (never edited by hand, step 18) and are re-exported by `src/types/database.ts`, which also narrows what the app may send to the columns it is granted. Gemini output types are server-only and live with the Edge Function.

Keep types simple and readable.

Type navigation with `RootStackParamList` (`src/navigation/types.ts`) and screen props with `NativeStackScreenProps<RootStackParamList, "Name">`. No `any`.

Ambient declarations (`*.svg`, `expo/types`) live in committed files under `src/types/`. Do not rely on the generated `expo-env.d.ts`: Expo CLI deletes it, and typecheck then fails on `import "./global.css"`.
